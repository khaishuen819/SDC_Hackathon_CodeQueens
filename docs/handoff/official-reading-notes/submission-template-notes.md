### Impact framework - every requested metric

Establish impact baseline before building prototype. If exact data is unavailable use estimates, published research or public benchmarks, and cite sources. Judges use target, baseline and KPI for **Innovation and Creativity** and **Feasibility of build** shortlisting assessments. Vague unsupported projections weaken advancement.

| Metric | Required response / example shown |
|---|---|
| Target SDG Sub-Target(s) | Exact UN target, not only SDG number; example Target 11.6 on urban environmental impact, air quality and waste management |
| Current Problem Baseline | Numeric starting condition; sample 35% energy inefficiency due to poor scheduling |
| Core Measurable KPI | Specific measurement unit; sample power reduction %, latency improvement, kilograms of waste avoided |
| Phase 2 Impact Target | Realistic percentage-based target by final prototype presentation; sample 20% computational resource improvement |

### Readiness checklist - all four items

1. All members have completed mandatory GenAI, Database and Cloud Deployment upskilling workshops.
2. Verified real-world problem mapped to one or more UN SDGs.
3. Solution targets a functional deployed application.
4. All fields complete within limits.

### IP and originality - every category

- **Pre-existing/prior-owned work:** any team-created/owned code, design, research or other work from before event. Mark yes/no. If yes explain what, and which member(s) own it. This form disclosure does not eliminate registration-time approval requirements from the handbook.
- **Third-party code/datasets/models:** libraries, open-source frameworks, public/private data and pretrained models not created by team. Mark yes/no; table **Name / Type (code/dataset/model) / License**. Open source is allowed if declared and properly licensed/attributed.
- **Employment-related IP:** any member's employment, internship or consulting agreement under which employer could claim work made during the hackathon. Mark yes/no; if yes describe agreement and member.
- **Final declaration:** leader confirms information accurate to best of team's knowledge and project original work made during SDC 2026 hacking period; signature/date.

### AI development declaration nuance

- The form states that declaring AI tools **does not reduce score; undeclared use may**.
- Declare development assistance separately from models running inside the final application.
- Name/version, exact tasks and extent of use are requested; then explain how team reviewed, tested and took responsibility within 100 words.
- This does not waive handbook requirements that team members understand the project, originate core framing/decisions and review/adapt AI outputs.

### Compliance checklist - all seven items

1. All APIs/cloud/AI tools/models/datasets declared.
2. Third-party code/data/models comply with licenses and attribution.
3. No API keys/passwords/credentials exposed in repository, prototype or declaration.
4. Generative AI development use disclosed and reviewed.
5. Sponsor resources declared in Section 5.
6. Prototype accessible to judges using Section 1 links.
7. All fields completed within word limits.

## Practical implications and gaps

- There are **two separate named PDFs**: proposal and technical declaration, in addition to repository template's Replit/RunPod proof files and other submission deliverables required elsewhere.
- The technical form extends beyond proposal's IP table: versioned dependencies, API tiers, cloud plan/region, model provenance/usage/licenses, dataset provenance/sensitivity, AI assistance extent/review, sponsor resources/replaceability, privacy/retention and limitations/mitigations.
- The template ZIP lacks the standalone Technical Tools Declaration; using only ZIP contents omits these detailed disclosure categories.
- Both sponsor/no-use yes/no form options and README's required Replit/RunPod sections exist. Follow official current operating requirements to decide tool obligations; a conditional form does not itself resolve that distinction.
- Placeholder technical declaration date must be resolved through organizer's current deadline announcement. Proposal's 25 October date is still missing a time.
- Prior work and employer conflicts should be declared honestly; proposal declaration of original work does not silently override expressly disclosed, approved prior materials.
- All source PDF pages reviewed; no domain-specific content beyond general domain-selection fields.
